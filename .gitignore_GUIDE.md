# .gitignore Guide

## Overview
This project has three `.gitignore` files to properly exclude sensitive and generated files from version control.

## Files Created

### 1. Root `.gitignore`
**Location**: `/.gitignore`

**Purpose**: Handles project-wide exclusions

**Key Exclusions**:
- ✅ `.env` files (all variants)
- ✅ OS-specific files (.DS_Store, Thumbs.db)
- ✅ IDE files (.vscode, .idea)
- ✅ Log files
- ✅ Temporary files

### 2. Backend `.gitignore`
**Location**: `/backend/.gitignore`

**Purpose**: Node.js/Express backend exclusions

**Key Exclusions**:
- ✅ `.env` files (CRITICAL - contains API keys!)
- ✅ `node_modules/` directory
- ✅ User uploads (except sample images)
- ✅ Log files
- ✅ Build artifacts
- ✅ PM2 files

**Special Handling**:
```
uploads/*              # Ignore all uploads
!uploads/.gitkeep      # Keep folder structure
!uploads/*.png         # Keep sample course images
uploads/avatars/*      # Ignore user avatars
!uploads/avatars/.gitkeep  # Keep folder structure
```

### 3. Frontend `.gitignore`
**Location**: `/frontend/.gitignore`

**Purpose**: Flutter/Dart frontend exclusions

**Key Exclusions**:
- ✅ `.env` files (CRITICAL - contains API keys!)
- ✅ `.dart_tool/` directory
- ✅ `build/` directory
- ✅ Platform-specific files (iOS, Android, Web)
- ✅ Generated files (*.g.dart, *.freezed.dart)
- ✅ Build artifacts (.apk, .ipa, .aab)
- ✅ Firebase config files

## Critical Files to NEVER Commit

### Backend
```
backend/.env                    # Contains:
  - RAZORPAY_KEY_SECRET        # Payment gateway secret
  - JWT_SECRET                  # Authentication secret
  - MOODLE_TOKEN               # Moodle API token
  - SMTP_PASS                  # Email password
```

### Frontend
```
frontend/.env                   # Contains:
  - NEXT_PUBLIC_RAZORPAY_KEY_ID  # Payment gateway key
  - API_BASE_URL               # API endpoints
```

## Verification

### Check if .env files are ignored:
```bash
git status
```

You should NOT see:
- `backend/.env`
- `frontend/.env`
- `.env`

### Check what will be committed:
```bash
git add .
git status
```

### If .env files appear in git status:
```bash
# Remove from git tracking (keeps local file)
git rm --cached backend/.env
git rm --cached frontend/.env
git rm --cached .env

# Commit the removal
git commit -m "Remove .env files from tracking"
```

## Setting Up on New Machine

When cloning the repository on a new machine:

1. **Clone the repository**
   ```bash
   git clone <repository-url>
   cd <project-directory>
   ```

2. **Create backend .env file**
   ```bash
   cd backend
   cp .env.example .env  # If you have an example file
   # OR create manually
   nano .env
   ```
   
   Add your credentials:
   ```env
   RAZORPAY_KEY_ID=rzp_live_xxx
   RAZORPAY_KEY_SECRET=your_secret
   JWT_SECRET=your_jwt_secret
   MOODLE_TOKEN=your_moodle_token
   # ... etc
   ```

3. **Create frontend .env file**
   ```bash
   cd ../frontend
   nano .env
   ```
   
   Add your configuration:
   ```env
   APP_ENV=dev
   API_BASE_URL_LOCAL=http://localhost:9000/api
   NEXT_PUBLIC_RAZORPAY_KEY_ID=rzp_live_xxx
   # ... etc
   ```

4. **Install dependencies**
   ```bash
   # Backend
   cd backend
   npm install
   
   # Frontend
   cd ../frontend
   flutter pub get
   ```

## Best Practices

### ✅ DO:
- Always add `.env` to `.gitignore`
- Use `.env.example` files (without secrets) as templates
- Document required environment variables
- Keep `.gitignore` updated
- Review `git status` before committing

### ❌ DON'T:
- Never commit `.env` files
- Never commit API keys or secrets
- Never commit `node_modules/`
- Never commit build artifacts
- Never commit user-uploaded files

## Common Issues

### Issue 1: .env file was committed
**Solution**:
```bash
# Remove from git history (dangerous - rewrites history)
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch backend/.env" \
  --prune-empty --tag-name-filter cat -- --all

# Force push (only if you're sure!)
git push origin --force --all
```

**Better Solution**: Rotate all secrets immediately!

### Issue 2: Large files in git
**Solution**:
```bash
# Remove large files
git rm --cached path/to/large/file

# Add to .gitignore
echo "path/to/large/file" >> .gitignore

# Commit
git commit -m "Remove large file from tracking"
```

### Issue 3: node_modules was committed
**Solution**:
```bash
# Remove from git
git rm -r --cached backend/node_modules

# Commit
git commit -m "Remove node_modules from tracking"
```

## File Structure Preservation

Some directories need to exist but should be empty in git:

```
backend/uploads/.gitkeep          # Preserves uploads folder
backend/uploads/avatars/.gitkeep  # Preserves avatars folder
```

The `.gitkeep` files are empty files that force git to track the directory structure.

## Security Checklist

Before pushing to remote repository:

- [ ] `.env` files are in `.gitignore`
- [ ] No API keys in code
- [ ] No passwords in code
- [ ] No tokens in code
- [ ] `node_modules/` is ignored
- [ ] User uploads are ignored
- [ ] Build artifacts are ignored
- [ ] Run `git status` to verify

## Support

If you accidentally commit sensitive data:
1. **Immediately** rotate all exposed credentials
2. Remove from git history
3. Force push (if repository is private and you're the only user)
4. Contact your team/security officer

**Remember**: Once pushed to a public repository, consider all secrets compromised!
